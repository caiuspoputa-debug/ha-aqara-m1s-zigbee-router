Aqara M1S Zigbee Coordinator + Router v0.36.8 TEST validation

Validation performed for this package on 2026-10-05:
- All Python files compile.
- manifest.json reports version 0.36.8.
- manifest.json, strings.json and both translations parse as JSON.
- The upload labels state that one WAV file can be uploaded at a time and do
  not advertise ZIP upload.
- All 48 isolated regression tests pass: 17 MQTT IO/coordinator, 7 shared
  MQTT, 9 WAV deletion, 8 WAV upload/storage, 4 clean audio shutdown and 3
  WAV priority/transport tests.

Availability regression coverage:
- MQTT callbacks never call `async_set_updated_data`, which previously changed
  `last_update_success` to true even for an `offline` LWT message.
- Every valid state, telemetry, `online` or `offline` message requests a main
  coordinator refresh, with bursts coalesced without losing the final state.
- A retained state payload cannot override a retained `offline` availability
  message during Home Assistant or MQTT reconnection.
- MQTT LWT is authoritative for all Coordinators and confirmed MQTT Routers;
  legacy Routers without the persistent agent retain the Telnet probe fallback.
- Consequently, Hub Connectivity and all CoordinatorEntity controls transition
  unavailable and available together.

Router MQTT WAV behavior:
- A Router must publish retained state with role=router and sound_mqtt=true
  before Home Assistant uses the MQTT WAV command path.
- Routers without that marker automatically keep the existing Telnet WAV path.
- MQTT carries only prepare and stop commands plus their status. Audio remains
  on the existing Home Assistant FFmpeg -> TCP 12347/12348 -> hub aplay path.
- Radio, media play/pause/stop, WAV and media-player volume, mute, PCM data and
  M1S Media Group synchronization are unchanged.
- The 500 ms clean WAV end cushion and suspend/restore priority sequence remain.

Live Router evidence:
- Router agent 1.1.1 was installed and left running on 192.168.0.200-209 and
  192.168.0.222-225.
- Each of those 14 hubs advertised sound_mqtt=true through its own configured
  MQTT broker and topic derived from its current IP.
- Each passed prepare, both TCP listeners 12347/12348, stop and listener cleanup.
- Router 192.168.0.221 remains part of the deployment scope but was unreachable,
  so it was skipped without modification and must be updated when it returns.
- Every changed hub received an on-hub backup before service replacement; no
  rollback was needed.

WAV upload guarantees retained from 0.36.5:
- Configure accepts exactly one WAV per operation; ZIP is not accepted.
- Capacity preflight runs before the progress dialog through a dedicated client;
  insufficient space returns the 8 MiB reserve error immediately.
- The transfer uses a separate short-lived client, so runtime polling cannot hold
  the upload behind the shared client lock.
- WAV validation requires uncompressed PCM, mono, 32000 Hz, 32-bit little-endian
  and limits a file to 20 MiB.
- Capacity checks account for replacement and preserve at least 8 MiB on /data.
- TCP and Telnet/Base64 transfer paths report monotonic measured progress and
  success requires remote size and MD5 verification.
