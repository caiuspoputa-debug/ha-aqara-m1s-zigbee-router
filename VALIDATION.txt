Aqara M1S Zigbee Coordinator + Router v0.37.5 TEST validation

Validation prepared for this package on 2026-10-07:
- All integration and regression-test Python files compile.
- manifest.json reports version 0.37.5.
- manifest.json, strings.json and both translations parse as JSON.
- The Router compatibility shell script passes shell syntax validation.
- All 66 isolated regression tests pass: 20 MQTT IO/coordinator, 7 shared
  MQTT, 9 WAV deletion, 8 WAV upload/storage, 11 audio transport, 8 group-loss
  simulations and 3 WAV priority/transport tests.

Individual volume precision added in 0.37.5:
- Every individual player preserves four normalized decimal places, equivalent
  to 0.01 percentage point.
- Native individual volume-up/down and the exposed step use the same precision.
- Volume remains live PCM software gain and does not restart the stream.
- Fine Volume Trim remains available internally and is unchanged.

Group volume precision added in 0.37.4:
- The group entity preserves four normalized decimal places, equivalent to
  0.01 percentage point.
- Native group volume-up/down and the exposed step use the same precision.
- Volume remains live PCM software gain and does not restart or resynchronise
  the radio stream.
- Individual volume and per-hub Fine Volume Trim are unchanged.

Group recovery changed in 0.37.3 after the 0.37.2 live test:
- Automatic complete-cohort pause/rebuild was removed.
- Synthetic 35-999 ms cursor delays remain on the live timeline.
- A 1000 ms cursor delay quarantines only the affected receiver.
- One 1.25-second TCP drain timeout is tolerated; two consecutive timeouts
  quarantine only the affected receiver.
- Three consecutive stale/XRUN ALSA samples are required before quarantine.
- Shared-history overrun also quarantines only the affected receiver.
- Healthy receivers, the common playout clock, media intent and FFmpeg source
  remain live during every automatic member recovery path.
- No automatic recovery path calls the complete timeline restart, group STOP or
  the removed broadcaster-pause mechanism.
- Full timeline resync remains an explicit user service only.

Retry-storm repair:
- A reconnect is successful only after PCM-history prefill, live catch-up and
  final admission all complete.
- The retry counter is not reset when a socket merely opens.
- Failed joins back off through approximately 1.5, 3, 6, 12 and 15 seconds.
- Successful admission resets the counter and clears the member error.
- Group diagnostics expose quarantined_hubs, member_prepare_failures and
  member_last_error.

Coordinator unload safety retained from 0.37.1:
- Integration unload, reload and update close only local Coordinator sockets.
- The persistent Coordinator TCP/UART relay on port 1886 is never stopped.
- Temporary Router sideband UART tunnels retain their existing cleanup.

Availability regression coverage retained from 0.36.9:
- Hub Connectivity is online when either MQTT IO or Telnet independently proves
  the physical hub reachable, and offline only when both paths are down.
- The sensor exposes connection_source without coupling general availability to
  optional MQTT-only diagnostics.
- Retained state cannot override retained offline availability during reconnect.
- Hub Connectivity and dependent CoordinatorEntity controls transition together.

WAV upload and playback guarantees retained:
- Configure accepts exactly one WAV per operation; ZIP is not accepted.
- Capacity preflight runs before progress and preserves at least 8 MiB on /data.
- The dedicated transfer client prevents normal polling from holding the upload.
- WAV validation requires PCM mono, 32000 Hz, signed 32-bit little-endian and a
  maximum file size of 20 MiB.
- Transfer success requires matching remote size and MD5.
- Stored WAV priority still suspends media, plays the WAV, then restores the
  remembered individual or group playback.
- MQTT transports only receiver prepare/stop commands, never radio PCM.

No JN5189 firmware write or flash is performed by this integration package.
